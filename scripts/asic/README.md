# ASIC synthesis and post-synthesis simulation

X-HEEP can be synthesized with two tools for two technologies, and every
resulting netlist can be simulated at gate level with QuestaSim:

| Flow           | Tool                     | Technology       | Design kit |
|----------------|--------------------------|------------------|------------|
| `yosys-ihp130` | Yosys + yosys-slang      | IHP-SG13G2       | `$IHP130`  |
| `yosys-tsmc65` | Yosys + yosys-slang      | TSMC 65nm LP     | `$TSMC65`  |
| `dc-ihp130`    | Synopsys Design Compiler | IHP-SG13G2       | `$IHP130`  |
| `dc-tsmc65`    | Synopsys Design Compiler | TSMC 65nm LP     | `$TSMC65`  |

No file of the design kits lives in this repository: export the kit root
before running a flow, and keep the outputs (netlists, reports, converted
`.db` files) private, as they are PDK-derived.

## Design kits

- `IHP130`: IHP Open PDK root (the directory that contains `libs.ref/`, or its
  parent).
- `TSMC65`: TSMC65 design-kit root. The flows look for the usual TSMC layout
  under it (`Front_End/` of the digital kit, possibly under `digital/`, and the
  memory-compiler output in `memory/sram/generated/`): see the header of
  [tech/tsmc65.tcl](tech/tsmc65.tcl).

Every file is located by [tech/ihp130.tcl](tech/ihp130.tcl) /
[tech/tsmc65.tcl](tech/tsmc65.tcl), the single description of each technology
read by all the flows. Each resource can be forced with its own variable (e.g.
`TSMC65_STDCELL_LIB`, `TSMC65_SRAM_DIR`), named in those files. To see what a
kit provides, and what is missing:

```bash
make asic-tech-check TECH=tsmc65
```

Design Compiler needs the libraries as `.db`. TSMC ships them next to the
Liberty files; the IHP Open PDK does not, so convert them once (with
`lc_shell`, into `build/tech_db/ihp130/`):

```bash
make asic-tech-db TECH=ihp130
```

## Running a flow

```bash
make mcu-gen                        # as usual
make dc-tsmc65                      # or yosys-ihp130, yosys-tsmc65, dc-ihp130
make dc-tsmc65-stage-netlist        # prepares the netlist for simulation
make app PROJECT=hello_world LINKER=flash_load
make questasim-build-postsynth
make questasim-run-postsynth        # boots from flash, bounded by POSTSYNTH_MAX_CYCLES
```

- Outputs: `build/<core>/asic_<tool>_<tech>-<edatool>/` (`asic_x_heep_system.v`
  for yosys; `x_heep_system_netlist.{v,sdc,sdf,ddc}` and `report/` for DC), and
  the log `build-<tool>-<tech>.log` in the repository root.
- DC clock period: `ASIC_CLK_PERIOD=<ns>` (default 20 ns for ihp130, 10 ns for
  tsmc65); constraints in [../synthesis/dc/constraints.tcl](../synthesis/dc/constraints.tcl).
- Every flow needs the design kit of its technology: without it, synthesis
  stops at once with an error.
- The yosys flow reads the interface of the IHP cells the RTL instantiates
  directly from black-box stubs (`hw/asic/ihp-sg13g2/rtl/cells/ihp_sg13g2_blackbox_stubs.sv`),
  since yosys-slang elaborates before the Liberty files are read.

## How it fits together

- **Synthesis top**: `x_heep_system_synth_top`, generated by
  [../synthesis/generate_synth_top.py](../synthesis/generate_synth_top.py):
  `x_heep_system` minus its unused CV-X-IF interface ports. For DC
  (`--plain-ports`) its struct ports become plain vectors, so both tools give
  the netlist the same port names and widths.
- **Technology cells**: `hw/asic/ihp-sg13g2/` and `hw/asic/tsmc65/` map the
  generic clock cells, the pads and `sram_wrapper` onto library cells and SRAM
  macros; the fusesoc targets `asic_<tool>_<tech>` in `core-v-mini-mcu.core`
  pick them.
- **Hierarchy** is kept by both tools, so the RTL instance paths
  (`x_heep_system_i.core_v_mini_mcu_i...`) exist in every netlist.
- **Staging** (`make <tool>-<tech>-stage-netlist`) copies the netlist to
  `implementation/postsynth/`, records its technology there (`asic_tech`),
  prefixes its modules with `ps_` (they would otherwise clash with the RTL
  compiled for the testbench) and generates the shim that gives it back the
  interface of `x_heep_system` for the unmodified testbench.
- **Simulation** (`sim_postsynthesis` target) compiles the technology's
  functional Verilog models into the QuestaSim library `pdk_lib`, zero-delay
  (`+nospecify +notimingcheck`, plus the technology's defines), and boots the
  firmware from the SPI flash model (`+boot_sel=1`).
- **Verilator** (experimental, verified target: yosys-ihp130): after staging,
  `make verilator-build-postsynth` and `make verilator-run-postsynth` simulate
  the same netlist with the Verilator testbench (`tb_top.cpp`, booting from
  flash). Verilator cannot use the PDK std-cell models (sequential UDPs,
  flops clocked through specify-driven nets), so
  [../sim/verilator/gen_postsyn_cells.tcl](../sim/verilator/gen_postsyn_cells.tcl)
  models the std cells from the Liberty (functions, flip-flops, latches,
  clock gates) and adds the PDK's own IO-pad/SRAM models. Verilator is
  2-state: it checks the netlist's function, not its X-safety (QuestaSim
  does both).
- `make questasim-trace-postsynth` writes a text trace of the CPU bus and boot
  pins for offline debugging. It reads the internal OBI ports by the names
  Yosys gives them; on DC netlists (which split struct ports by member) those
  signals are reported as `SKIPPED`.
